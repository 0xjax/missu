# Reviewing by Isomorphism（同构背书评审）

## Overview

生产安全记录背书的从来不是代码文本，而是「代码 × 数据不变量 × 失败模式 × 执行上下文」的组合。改动中与旧代码四维同构的部分，继承旧代码的实证安全，评审可降级；任一维度断裂，背书作废，该部分按全新代码对待。

## 方法

1. 把改动切成**语义增量**（不按文件/提交粒度）。
2. 每个增量找它在旧代码中的对应物，逐维度比对：

| 维度 | 问什么 | 断裂的典型形态 |
|---|---|---|
| 控制流 | 调用链形状一致？ | 新增分支、新调用方 |
| 数据不变量 | 读写同一批约束下的同一批数据？ | 操作对象的归属/约束语义改变 |
| 失败模式 | 重试、超时、部分失败路径一致？ | 回滚操作可触及他人已提交状态 |
| 执行上下文 | 规模、触发时机、调用方信任级别一致？ | 人工圈选几十人 → 定时全量数万人 |

3. 四维全同构 → 行为等价 → **降级评审**（抽样确认即可，不必逐行）。
4. 任一维度断裂 → 背书失效 → **升级验证**（测试、数据回放），此处吃掉全部评审深度。

## 核心规则

- **承重的差异永远藏在 "same as old, except…" 的 except 里。** 听到「与旧代码同构 / 复用 / 照抄旧模式」，第一反应是主动找出那个 except；找到并逐维度核对之前，背书不成立。差异不会被主动申报。
- **同构背书只担保「无新增误伤」，不担保「新逻辑本身正确」。** 意图与代码一致 ≠ 逻辑无 bug；正确性永远属于测试，两者正交。
- **背书是评审资源的分配器，不是免测试金牌。** 同构部分放行省下的深度，全部投给非同构的 20%——那里承担 100% 的新风险。

## Common Mistakes

- **文本相似当同构**：形状相同的代码段，操作对象语义已变（见下方实例）。
- **用旧记录背书新上下文**：旧代码的生产历史只覆盖旧规模/旧触发方的分布；规模或调用方变化即零覆盖。
- **恒真判断当永久事实**：「枚举只有两值所以门控恒真」是快照结论，需核实枚举全集且被删代码无副作用。
- **同构结论外推为正确性结论**：放行 ≠ 正确。

## Real-World Example

发券 worker 重写中，「失败时删除当日幂等键」与旧模式表面同构，但旧代码只删**本次运行自己创建**的键，新代码可能删到**上一次成功运行**的键——数据不变量维度断裂，自我回滚变成销毁他人成功标记，重试即重复发券。该 bug 由后续修复提交补上；同构检查若执行到位，应在此处拦下。
