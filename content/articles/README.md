# 公开文章集

这里保存首页「随机阅读」的公开终稿。文章随应用版本更新，构建后写入 `app/src/main/assets/articles.json`，运行时完全离线读取，不进入诗文数据库，也不使用远程内容服务。

## 私人原稿与公开终稿分离

`D:\ob-vault\growth\性与成瘾\` 及类似私人笔记目录只能作为人工选题和改写的素材来源，**不是构建输入**。禁止脚本遍历、复制、提交或打包原始目录；`protected` 标记不等于已脱敏，也不表示只要删除该标记就能发布。

只有独立重写、人工复核后的终稿才能进入 `sources/`。收录边界如下：

- 只选择可独立成立的通用理论、科普和自助知识。具体性经历、消费事件、关系实录、自伤经历及涉及伴侣或其他第三人的私密内容不收录，不做简单匿名化后收录。
- 公开稿必须重新组织表达，不能只替换姓名、城市或金额。删除可组合识别个人或第三人的时间、地点、财务、职业、关系和事件细节。
- 不保留原始文件名、写作日期、Frontmatter、Obsidian 双链、附件、原始路径或外部链接；源文件与公开 ID 的对应关系也不写入仓库。
- 科学和临床表述应保留证据边界，不夸大神经科学结论，不根据文章自行诊断或用药。涉及即时危险时只提供通用求助指引。
- 自动校验用于发现明显遗漏，不能证明内容已脱敏。每篇文章提交前仍需人工按上述边界审阅；测试与文档只能使用虚构示例。

## 格式与更新

每篇文章是 `sources/<id>.json`：

```json
{
  "id": "stable-english-id",
  "category": "通用分类",
  "title": "公开标题",
  "summary": "首页摘要",
  "paragraphs": ["正文第一段", "正文第二段", "……"]
}
```

正文使用结构化段落，由 Compose 原生排版，不引入 Markdown 渲染器。界面按钮与页面标题仍走四语言字符串资源；文章正文是内容数据，不放进 `strings.xml`。

```powershell
bun run articles:build
```

脚本校验 ID、文件名、正文和常见敏感信息，按文件名排序生成 assets 与 `manifest.json`。两者都是构建产物，禁止手改；新增、修改或撤下文章后重新执行命令并随应用版本发布。
